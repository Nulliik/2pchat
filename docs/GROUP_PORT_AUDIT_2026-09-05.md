# Проверка групп при переносе Python → Go, 2026-09-05

Исходный документ: `GROUP_CHATS_ANALYSIS_AND_IMPROVEMENTS_2026.md` из Downloads/Telegram Desktop. Его рекомендации проверены по исходникам; сроки, обещания ускорения и предложения новых функций не считаются подтверждёнными результатами.

> Исторический срез переноса: указанная ниже схема v6 относится к моменту проверки. Текущий Go-клиент уже использует v7; актуальная спецификация — [GROUP_CHAT_PROTOCOL.md](GROUP_CHAT_PROTOCOL.md). Журналы запусков являются локальными артефактами и не входят в Git.

## Где находится реализация

Групповой runtime, SQLCipher, ACL и Compose остаются в Kotlin. В старом дереве `2PChat android/android` подписи делегируются `PythonBridge`, в `2pchatGO/android` — `NativeBridge` и Go. Отдельного Python runtime групп в `messenger` нет.

Python: `messenger/discovery_bridge.py`, функции `get_local_signing_public_key`, `sign_group_payload`, `verify_group_payload`. Подпись Ed25519 использует контекст `2pchat-group-event-signature-v2\0`; при приёме поддерживаются старые контексты Python v1 и Go v1. Go реализует те же варианты в `core-go/pkg/crypto/group.go`; совместимость проверяется `interop_test.go` и Android-подписями независимого ключа.

## Исправления

1. На группу допускается один sync-сеанс и один ожидаемый пакет. Курсоры авторов разбиваются по 256 и обрабатываются последовательно. Ответ привязан к request ID, группе и аутентифицированному пиру; незапрошенные и просроченные ответы не применяются. Таймаут 15 секунд учитывает Tor; после отсутствия ответа или трёх пакетов без прогресса выбирается следующий пир. Выбор постепенно обходит пиров, чтобы один неполный архив не стал единственным источником истории.
2. Для обычных событий до 32 получателей сохранена прямая доставка; выше — три долговременные HRW-реплики и до трёх подключённых соседей по детерминированному кольцу. Каждый первый получатель ретранслирует событие один раз. Обрезка произвольного префикса roster удалена. Сериализованные изменения членства продолжают доставляться всем требуемым получателям.
3. Reconnect переотправляет ключ только подключившемуся участнику. Периодический sync больше не имитирует reconnect каждого пира, не сбрасывает backoff очереди и не повторяет уже подтверждённые ключевые пакеты.
4. При получении истории обновление UI и read receipt выполняются на пакет. Транзакционная обработка каждого события и его проекций сохранена.
5. Typing проверяет совпадение device ID с транспортным отправителем и самостоятельно исчезает через пять секунд.
6. Исправлена Android-фикстура: для Ed25519 в AndroidKeyStore явно задаётся `ECGenParameterSpec("ed25519")`. Иначе исходная фикстура генерировала неподходящий EC-ключ. Это согласуется с [реализацией AndroidKeyStore](https://android.googlesource.com/platform/frameworks/base/+/80a664262667cf14ee1ae52ab7c53abc26e17d1e/keystore/java/android/security/keystore2/AndroidKeyStoreKeyPairGeneratorSpi.java).

## Воспроизводимость

```powershell
.\.venv\Scripts\python.exe -m pip install -r messenger/requirements.txt
.\.venv\Scripts\python.exe -m pytest
# Из 2pchatGO/android/core-go:
go test ./...
# Из 2pchatGO/android:
.\gradlew.bat -PgroupQaApplicationId=com.example.twopchat.groupqa testDebugUnitTest assembleDebug assembleDebugAndroidTest
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w -r -e package com.example.twopchat.group com.example.twopchat.groupqa.test/androidx.test.runner.AndroidJUnitRunner
# Повторить установки и instrument для emulator-5556.
# Из корня репозитория, с adb в PATH либо переменной ADB:
.\.venv\Scripts\python.exe tools/android_group_e2e.py
```

Инструментальные тесты очищают свои группы, поэтому используется отдельный application ID `com.example.twopchat.groupqa`. Установленные `com.example.twopchat.go` не очищаются. E2E-команды доступны только в debug и дополнительно проверяют QA application ID; listener работает на порту 51001, ADB forwards — 55154/55156.

## Границы подтверждения

Реальная межпроцессная проверка использует два эмулятора и Go-транспорт через ADB TCP forwarding. Это не испытание тысячи физических Android-устройств и не проверка всех вариантов Tor/Yggdrasil/NAT. Моделирование кольца проверяет охват 2/20/33/129/500/1000 участников, отключённого автора и половину roster; для 10 000 проверяется ограничение числа адресатов. Полносвязная доступность онлайн-участников в этих моделях — явное допущение; произвольные разрывы сети восстанавливаются anti-entropy, а не гарантируются кольцом.

UI performance-тест использует 600 сообщений с медиа. Он проверяет регрессионные пороги на эмуляторе, а не обещает конкретный FPS на реальном телефоне. Результаты запусков записываются в журналы `pytest-groups-20260905.log`, `go-groups-20260905.log`, `gradle-groups-complete-20260905.log`, `adb-groups-final-*-20260905.log`, `group-e2e-20260905.log`.
