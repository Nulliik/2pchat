# Отчёт по устранению замечания M3: Пустые catch блоки (Empty catch blocks)

## 1. Цель и контекст
Исключить скрытое подавление исключений (silent exception swallowing / empty catch blocks) во всей кодовой базе Android (`android/app/src/main/java`). 

Ранее пустые блоки `catch` приводили к следующим рискам:
1. **Маскирование сбоев**: ошибки ввода-вывода, транзакций БД, парсинга сетевых пакетов и инициализации криптографии не фиксировались в логах.
2. **Нарушение отмены корутин**: поглощение `CancellationException` в корутинах ломало структурированную конкурентность Kotlin Coroutines (`Job.cancel()`).
3. **Потеря прерывания потоков**: перехват `InterruptedException` в циклах сна без восстановления флага `Thread.currentThread().interrupt()`.
4. **Слишком широкие типы**: перехват `catch (_: Throwable)` скрывал критические ошибки виртуальной машины (`OutOfMemoryError`, `LinkageError`, `StackOverflowError`).

## 3. Архитектурные принципы и правила

1. **Сохранение отмены корутин (`CancellationException`)**:
   Во всех функциях, выполняющихся внутри CoroutineScope или помеченных `suspend`, перехват обобщённых исключений обязательно дополнен:
   ```kotlin
   catch (e: Exception) {
       if (e is CancellationException) throw e
       SafeLog.w(TAG, "Operation failed: ${e.message}")
   }
   ```
2. **Восстановление флага прерывания потоков (`InterruptedException`)**:
   В фоновых циклах с `Thread.sleep(...)`:
   ```kotlin
   catch (e: InterruptedException) {
       Thread.currentThread().interrupt()
       /* intentionally ignored: thread interrupted during shutdown/retry */
   }
   ```
3. **Сужение типов исключений**:
   Замена небезопасных `catch (_: Throwable)` на точные типы (`IOException`, `SQLiteException`, `ActivityNotFoundException`, `SecurityException`, `URISyntaxException`). Неперехватываемые ошибки виртуальной машины (`Error`) больше не поглощаются.
4. **Обоснованность подавления**:
   Любой блок, где подавление является нормальным ходом выполнения, снабжён комментарием с префиксом `/* intentionally ignored: <reason> */`.
5. **Безопасное логирование**:
   Все новые логи используют `SafeLog` и исключают логирование приватных данных (содержимое сообщений, секретные ключи, токены).
